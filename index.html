Full Migration Flow — SEEDS

JDK 1.4 + Interstage (session/XA/固有API) → JDK 21 + Spring Boot 3 (JWT/@Transactional/JPA) · AWS Multi-AZ

📘 Flow này KHÔNG chỉ là "sửa cú pháp". Chuyển framework = thiết kế lại class structure, package layout, DI, common layer, cross-cutting concerns.

Chia làm 5 phase lớn: Discovery (hiểu hiện trạng — gồm nghiệp vụ) → Analysis (nhận dạng gap cú pháp + nghiệp vụ) → Architecture Design (thiết kế hệ thống mới) → Detail Design (per-module design) → Build & Test.

Phase 3 (Architecture) là CORE của full framework migration, không có trong flow "pure syntactic upgrade".

2.2 — Semantic Analysis 意味解析 MANUALCORE

Phần CHÌA KHÓA của framework migration — không có skill tự động được, cần người đọc code + hiểu nghiệp vụ.

Nội dung cần capture per class:

Analysis dimensionNội dungVí dụ cho SEEDS
Class responsibility Class này làm gì về nghiệp vụ (1 câu) ApplyAction: "Nhận申込 từ 営業店, validate, lưu vào申込 table, trigger host-connect"
Method semantics Mỗi public method làm gì về nghiệp vụ (not just API signature) ApplyAction.execute(): orchestrate 3 steps = validate → persist → notify-host

Layering (unofficial) Class này đóng vai gì (Controller/Service/DAO/Entity/Util)? ApplyAction = pseudo-controller (Interstage servlet); ApplyDao = data access

Phase 3 — Architecture Design 🔥

3
Thiết kế hệ thống mới (Spring Boot 3) — không phải "fix API"
CORE PHASE MANUAL + AI-assisted Blueprint ra trước, detail sau. Decide package/common BEFORE touching code.

Đây là bước PHÂN BIỆT syntactic upgrade vs full framework migration. Nếu skip phase này → code mới sẽ chỉ là "old code with Spring annotations slapped on" → không tận dụng được Spring Boot, bug tiềm ẩn, maintenance khó.

Anti-patterns cần tránh:

❌ Legacy pattern As-Is
// Giant static util class
class CommonUtil {
  static String formatDate(...) {...}
  static int calcPremium(...) {...}  ← business!
  static Connection getDbConn() {...}
  static void writeLog(...) {...}
  // ... 50 more methods
}
→
✅ Split by concern
// Pure utility (if any)
class JapaneseEraConverter {...}

// DI'd component
@Component
class JpyFormatter {...}

// Business belongs to domain
contract/domain/PremiumCalculator

// Spring handles infra
spring.datasource.*
@Transactional

Common placement rules:

  1. Zero business logic trong common/. Business rules → feature package's domain/.
  2. Prefer composition over inheritance. Không tạo BaseController extends AbstractAction. Dùng @ControllerAdvice, interceptor, aspect.
  3. Custom common = ≥ 2 features dùng + ≥ 2 methods. Nếu chỉ 1 method hoặc 1 feature → không common.
  4. Document common contract: mỗi class common có JavaDoc nêu "Khi nào dùng? Khi nào KHÔNG dùng?"
Decision về common/shared là đầu vào cho Phase 4 detail design — mỗi GAP touching cross-cutting concern biết sẽ đặt code vào common hay feature package.
3.4 — Cross-cutting Concerns MANUAL

Design cách handle cross-cutting (dùng Spring facilities):

Session → JWT (SEEDS Multi-AZ mandate):

As-Is (Interstage session)
HttpSession sess = req.getSession();
sess.setAttribute("userId", "U001");
sess.setAttribute("role", "ADMIN");
// Stored on Interstage AP server
// Dies on failover
→
To-Be (JWT, stateless)
// JWT contains userId + role claims
@AuthenticationPrincipal UserContext ctx;
ctx.getUserId();
ctx.hasRole("ADMIN");
// Multi-AZ safe, no server state
// Token in Authorization header

Transaction (XA → @Transactional):

As-Is (Interstage XA)
UserTransaction tx =
  (UserTransaction) ic.lookup("java:comp/UserTransaction");
tx.begin();
try {
  // DB ops
  tx.commit();
} catch (Exception e) {
  tx.rollback();
}
→
To-Be (@Transactional)
@Service
public class ContractService {
  @Transactional
  public void register(ContractRequest req) {
    // DB ops: auto commit/rollback
  }
}
// For distributed TX across services:
// Outbox pattern + SQS, không XA

Logging & audit:

As-Is
LogUtil.log("TRACE", "ApplyAction",
  "execute() start uid=" + userId);
LogUtil.logAudit(userId, "APPLY",
  contractId);
→
To-Be (SLF4J + aspect)
// Business log
private static final Logger log =
  LoggerFactory.getLogger(ContractService.class);
log.info("register start uid={}", userId);

// Audit via @AuditLog aspect
@AuditLog(action = "APPLY")
public void register(...) {...}
3.5 — Data Model (JPA Entity + Repository) MANUAL

Chuyển từ DAO + manual JDBC → JPA Entity + Spring Data Repository. Decide:

  • Entity per table: 1-1 mapping, @Entity + @Column
  • Relationship: @ManyToOne lazy by default, @OneToMany fetch lazy
  • Repository: extend JpaRepository, custom queries via @Query hoặc method naming
  • Native SQL cũ: giữ nếu complex (reporting), convert sang @Query(nativeQuery=true)
  • Pro*C → Spring Batch: cursor-based batch processing dùng ItemReader + ItemWriter
